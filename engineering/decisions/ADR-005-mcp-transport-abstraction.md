# ADR-005：将 MCP 传输与工具适配分离

## 决策

Moka 使用统一的 `McpClient` 接口和客户端工厂，将 stdio 与 Streamable HTTP 实现为独立传输客户端。MCP 工具发现和 Tool Registry 适配保持在公共层，不让权限、参数校验和 Trace 感知传输类型。

## 背景

早期 MCP Client 直接把子进程生命周期、JSON-RPC 和工具适配放在一个类中。继续在同一类中加入 HTTP、SSE、session 与网络异常，会使本地进程和远程网络状态相互耦合，也会诱发两套工具权限与审计逻辑。

## 取舍

- 单类条件分支：改动小，但状态机难以测试，后续 OAuth 会继续增加耦合；
- 双客户端、统一接口：文件增多，但传输状态、测试和失败策略独立；
- 独立 MCP Gateway：适合多服务生产部署，但超过个人项目当前验证范围。

选择双客户端、统一接口。上层仅调用 `list_tools()`、`call_tool()` 与 `close()`。

## 结果

- 原 stdio 配置的前三个位置参数保持兼容；
- HTTP 工具继续进入原有 Tool Registry、权限检查和运行轨迹；
- 新传输不会形成权限旁路；
- 完整 OAuth 和旧 SSE 协议兼容保留为后续需求。
