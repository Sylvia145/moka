# 生成 learn 学习知识库文档（通用版）

把"基于简历/成果 + 继承设计，生成一套纯学习文档"的完整流程固化成可重复执行的步骤。本 skill 的产物是一套编号文档（默认 `.local-notes/learn/NN-*.md`），服务于**把整个系统讲透**；不掺面试话术（面试材料另立）。本 skill 与项目无关：流程、体例、模板、检查点都通用，唯一要按项目调整的是**源码路径、测试命令、文档目录**三处（见"按项目适配"）。

## 何时使用 / 不何时使用

- **使用**：用户说"把 XX 讲透""生成学习文档""根据简历写 learn 文档""整理成知识库"——目标是"理解系统、能用自己的话讲清解决什么问题 + 怎么实现 + 代价"。
- **不使用**：用户要的是 API 参考、速查表、README、面试应答稿（那些是别的产物，不是 learn 库）。

## 前置：先定目标与范围

1. **收集输入**：读用户提供的简历/成果条目；读项目结构（AGENTS.md / CLAUDE.md / 源码树）；确认目标文档目录是否已存在（`learn-docs` 默认 `.local-notes/learn/`，若项目已有约定文档目录则用项目约定）。
2. **抽取成果**：把简历每条成果转成"要在文档里讲透的能力"，例：`证据链`、`远程 MCP 幂等重试`、`Worker worktree 隔离`、`评测回归`。
3. **定文档集**：默认用下方 13 篇模板，按项目实际裁剪——少一个领域就少一篇，多一个领域就加一篇。模板针对"agent runtime"类系统设计；Graph RAG / 微服务 / 其他类型项目把对应领域的篇目换成自己的核心子系统（如 `pipeline-ingestion`、`graph-indexing`、`query-retrieval`）。编号即阅读顺序。
4. **建映射**：先写"成果 → 文档篇"表，再写"ADR → 文档篇"表（若项目有 ADR/INC/迭代留痕），两表进收口索引。
5. 把规划结果告诉用户，**确认后进入分阶段写作**。

## 文档集模板（13 篇，编号即顺序，可按项目替换领域篇）

- `00-index.md` — 阅读索引：文档地图（Mermaid）、覆盖清单勾选、简历→文档映射表、ADR↔文档映射表、学习库定位说明
- `01-overall-system.md` — 系统总览：分层架构、一条请求的完整生命周期、对象图（谁持有谁）
- `02-core-engine.md` — 核心引擎：主循环/状态机、协议、模型或任务解析、终结治理（runtime/agent 项目）或核心处理管线（其他项目）
- `03-action-execution.md` — 动作/任务执行边界链：注册、参数校验、权限接入点、副作用治理
- `04-permissions-sandbox.md` — 权限与隔离：每个"门/关卡"的决策语义、模式状态、沙箱
- `05-remote-integration.md` — 外部集成与可靠性：协议抽象、重试/幂等语义（对应 MCP/远程调用/外部依赖）
- `06-delegation-workers.md` — 委派与并发：worker/子任务隔离、降权、有界并发、超时取消、恢复
- `07-context-memory.md` — 上下文/状态管理与记忆：预算、压缩、分层缓存、持久状态
- `08-providers-config.md` — 适配层与配置：多后端收敛、错误分类恢复、配置优先级、secrets
- `09-persistence-recovery.md` — 持久化、恢复与证据规范化（状态落盘、可审计产物）
- `10-evaluation.md` — 评测回归：确定性 harness、判分公式、验证语义、实验聚合
- `11-surface-cli-tui-skills.md` — 用户面：CLI、命令系统、TUI、可扩展工作流（Skills）、branding
- `12-design-history.md` — 设计演进：ADR 逐篇、INC 复盘、迭代留痕、三链咬合

**边界归属原则**（防重复）：每篇只讲本层，跨层内容按"主归某篇、他篇一句交叉"。例：证据 schema 归 09、验证判定归 10；权限链接入点画在 03、每门语义归 04。拆分的两篇各加一条互指。

## 分阶段写作（每阶段配验证 + 固定格式报告）

按 1→12→00 顺序分 6 个阶段（可按规模合并；小项目可并为 3 个阶段）：

- 阶段 1：01 + 02（先建全局图）
- 阶段 2：03 + 04
- 阶段 3：05 + 06（简历重点，可单独拉长）
- 阶段 4：07 + 08
- 阶段 5：09 + 10
- 阶段 6：11 + 12 + 00（索引收口）

**每个阶段内固定四步**：

1. **读源码（先读后写，不允许边写边猜）**：把该篇涉及的关键文件**完整读一遍**，记下真实的函数签名、行号、常量、调用链。**记忆里的代码不可信**——凡是前一阶段/此前会话读过的文件，本阶段要用 Read/Grep 重新核对后才写入文档；严禁凭记忆贴代码。
2. **写文档**：按下方统一体例，一篇写完再写下一篇。
3. **验证**：跑该篇覆盖模块的测试。**测试命令取项目实际约定**——先读 AGENTS.md / CLAUDE.md / CI 配置 / 包管理器 scripts（`pyproject.toml` 的 pytest 配置、`package.json` 的 scripts 等）；Windows 下若 `uv run` 类 trampoline 或编码有坑，改用虚拟环境里的解释器直接跑（如 `.venv\Scripts\python.exe -m pytest`）。把真实结果写进文档"验证方式"节。同时用 Grep 校验文档里所有 `file_path:line` 引用存在。
4. **输出固定格式完成报告**：

   ```
   完成的文档 / 覆盖的运行时模块 / 验证命令与结果 / 引用到的 ADR·INC / 未覆盖或待确认点
   ```

## 统一体例（硬性要求，每篇遵守）

1. **这一层解决什么问题**：3–5 句，含反面（"没有它会怎样"）。
2. **核心概念先行**：先给"人话解释"再给术语；先讲设计意图再讲机制。
3. **关键实现与调用链**：从入口到出口；代码块 + Mermaid 图 + 逐段讲解。
4. **边界与取舍**：每个设计放弃了什么、为什么；含已知差距/未实现。
5. **验证方式**：能复跑的测试命令 / demo / 打开哪个工件核对。
6. **结尾"延伸阅读"**：列来源文档与关联文档。**不写面试应答话术**。

**代码与图必配讲解（不可省略）**：

- 每个代码块紧跟一段逐行/逐段讲解（变量含义、控制流、为什么这么写、与前后代码的关系）。禁止裸代码块。
- 每张 Mermaid 图（`flowchart`/`sequenceDiagram`/`stateDiagram`/`mindmap`）图后紧跟"按图走一遍"的逐步文字叙述（第 1 步…第 N 步），把每个节点和箭头翻译成文字。禁止裸图。
- 关键数据结构贴字段表格 + "每个字段是什么、何时写入、谁消费"。
- 示例要有延续性：每篇用一个贯穿全文的最小例子，同一例子在不同代码块/图里反复出现。

**写作约束**：

- 全中文撰写；代码标识符保留英文原名。
- 深度优先，篇幅以讲清楚为准，不设硬性上限（单篇 1000+ 行可接受）；宁可展开讲透，不赶工缩水。
- 每篇内部自洽完整，跨篇用交叉引用互指、不重复展开。
- 每篇开头列"前置"、结尾列"延伸阅读"。

## 收口（写完全部后必做）

1. **覆盖清单勾选**：用 00 索引里的清单逐项核对——每项都要能指向具体章节。
2. **映射表核对**：简历每条成果、每个 ADR/INC 都要能在正文找到讲解，回查可溯源。
3. **无裸代码块/裸图检查**：用脚本扫描相邻 fence（`^```$`）之间是否空/无文字，每篇 Mermaid 块后必须紧跟讲解；fence 总数须为偶数。
4. **通读抽查**：任取每篇 1–2 个代码块核对与真实源码一致。

## 按项目适配（迁移到新项目时改这三处）

| 适配点 | 默认 | 迁移到新项目时 |
|---|---|---|
| 文档目录 | `.local-notes/learn/` | 用项目约定的文档目录（或保持默认） |
| 源码路径 | 项目根下的源码树 | 把"覆盖的运行时模块"对应到实际包目录 |
| 测试命令 | 项目约定（读 AGENTS.md/CI/scripts） | 用新项目的真实测试命令，勿沿用旧项目命令 |

**迁移检查**：复制本 skill 到新项目的 `.claude/skills/learn-docs/` 后，先回答三问——① 文档放哪；② 源码在哪；③ 测试怎么跑——再把答案写进阶段 0 的规划，然后照流程执行。

## 边界与取舍

- **纯学习定位**：learn 库只服务"讲透系统"；面试口径、速查、演示脚本另立（索引里写一句即可）。
- **继承 vs 改造标注**：每个模块写明"基线继承还是本仓改造/新增"；改造点通常对应简历成果。标注只服务诚实理解。
- **诚实记录限制**：已知差距、未实现能力、环境 bug 如实写进"边界与取舍"/"待确认点"，不粉饰。

## 例子：通用落地形态

输入 = 简历 N 条成果 + 继承设计 + 源码树 → 输出规划 = 文档集（13 篇模板裁剪后）+ 两张映射表（成果→篇、ADR→篇）→ 6 个阶段逐篇写 + 每阶段验证 + 固定格式报告 → 收口 = 覆盖清单全勾 + 无裸代码块/裸图检查。任何项目（agent runtime / Graph RAG / 微服务）都按同一骨架执行，差异只在本 skill"按项目适配"表的三处。
