# 可审计记忆端到端演示

该演示将一次来源任务产生的 durable memory 交给新的 Session 使用，并用 Trace、report、Session 工件和文件锚点证明其来源、检索与失效决定。

## 复现

```powershell
uv run python scripts/run_memory_e2e_demo.py --mode scripted --output artifacts/engineering/memory-e2e/<run-id>/demo-summary.json
uv run python -m pytest tests/test_memory_e2e_demo.py tests/test_memory.py tests/test_usage.py -q
```

固定场景为配置替代、排障流程、发布护栏、多文件重构约定和依赖锚点失效。每个场景同时运行 memory-on 与 memory-off，两个变体使用相同最终 Verifier。

## 当前 scripted 结果

最终 artifact `artifacts/engineering/memory-e2e/final-20260902-r4/demo-summary.json`：5/5 场景通过；memory-on 与 memory-off 均为 5/5 最终 Verifier 通过。前四个可安全复用的场景合计减少 4 次重复文件读取和 4 个工具步骤；依赖锚点失效场景保留重新读取，以验证旧知识不会被错误复用。

## 录屏步骤

1. 展示来源 Session 的 `report.json` 中 durable promotion 与 `trace.jsonl` 中 `memory_promoted`。
2. 展示后续 Session 的 `memory_retrieved`、`memory.retrieval` 和最终 Verifier。
3. 输入 `/memory-evidence provider endpoint`，查看新事实的来源 Session、run、Trace、验证状态与 supersede 关系。
4. 展示依赖锚点变动后的 `stale_evidence` 拒绝；系统重新读取当前文件。

原始工件位于忽略目录 `artifacts/engineering/memory-e2e/<run-id>/`。真实模型运行需显式设置 `PICO_LIVE_SMOKE=1`，仅作为补充冒烟，不纳入确定性指标。
